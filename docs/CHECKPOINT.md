## 1) التشغيل على جهازك من الصفر

```bash
git clone <رابط المستودع>
cd roka                       # اسم المجلد كما استنسخته
git checkout claude/electronics-repair-shop-erp-dm0qfg

npm install

cp .env.example .env
# ولّد المفتاحين وضعهما في .env:
openssl rand -base64 48       # ← AUTH_SECRET
openssl rand -hex 32          # ← ENCRYPTION_KEY

npm run setup                 # توليد العميل + إنشاء الجداول + التعبئة
npm run dev
```

افتح <http://localhost:3000> ← `admin` / `Admin@12345` ثم **غيّر كلمة المرور**.

لبيانات تجريبية واقعية (30 عميلاً، 48 جهازاً، 36 أمر صيانة، 45 فاتورة):

```bash
npm run db:seed:demo
```

**تحقّقت من هذا المسار كاملاً عند نقطة التوقّف**: قاعدة جديدة → 22 إعداداً،
مستخدم مدير، 71 خدمة، 99 قالب إشعار، و`shop.name = FIXEL`.

### متطلّبات

- **Node 20 أو أحدث** (`engines` في package.json يفرضها)
- لا حاجة لقاعدة بيانات خارجية محلياً — SQLite ملف واحد في `prisma/dev.db`

## 3) قرارات معمارية — لا تنقضها دون سبب

هذه ليست تفضيلات، كل واحدة حلّت مشكلة حقيقية:

**المخطط بلا `enum` وبلا `Json`.** القيم المسموحة أنواع TypeScript في
`src/lib/constants.ts`. السبب: يبقى المخطط متوافقاً 100% بين SQLite وMySQL
وPostgreSQL. لو أضفت `enum` كسرت هذه الميزة.

**لا هجرات Prisma.** ملفات الهجرة SQL خاصة بمزوّد واحد، وهذا يناقض التصميم
أعلاه. نستعمل `db push`. الشرح الكامل في `docs/CPANEL.md`.

**`npm run db:mysql` إلزامي قبل النشر على cPanel.** Prisma يحوّل `String`
إلى `VARCHAR(191)` افتراضياً — بدون السكربت تُقتطع التواقيع الرقمية وتقارير
حالة الأجهزة وسجل التدقيق. السكربت يضيف `@db.Text`/`@db.LongText` لـ56 حقلاً.

**محرّك النص في `src/lib/pdf/text.ts` مكتوب يدوياً.** لأن `fontkit` يشكّل
الحروف العربية صحيحاً لكنه يرصّ الكلمات من اليسار، ولا ينفّذ خوارزمية
Unicode ثنائية الاتجاه. لا تستبدله بـ `doc.text()` المباشر — ستنقلب الجمل.

**العلامة مُعرَّفة في ثلاثة ملفات تتغيّر معاً**: `src/components/brand.tsx`،
`public/icon.svg`، `src/lib/pdf/brand.ts`. الأخير متّجهات لا صورة، لأن
العلامة تُطبع عند 8mm وأي PNG يهترئ هناك.

**الألوان متغيّرات CSS في `globals.css` فقط.** لا تكتب لوناً ثابتاً في مكوّن.

**القطع تُخصم عند إضافتها لأمر الصيانة، لا عند التسليم.** لذلك
`/invoices/new?repairId=` يحوّل بنود القطع إلى `CUSTOM` — وإلا خُصمت مرتين.

## 4) ما تحقّقت منه فعلياً مقابل ما لم أتحقق منه

### مُتحقَّق منه بالتشغيل

- بناء المشروع وفحص الأنواع يمرّان بلا أخطاء
- حزمة standalone تعمل: صفحة الدخول 200، CSS 200، RTL سليم، `/dashboard` يعيد 307
- توليد PDF للفاتورة والإيصال وعرض السعر بثلاث لغات — فحصتها بصرياً
- الروابط الموقّعة: صالح 200، منتهٍ 410، معدَّل/مفقود/مُعاد استخدامه 403
- إرسال الفاتورة عبر واتساب (رابط موقّع) وبريد (مرفق 31 كيلوبايت) — عبر متصفح حقيقي
- مخطط MySQL وPostgreSQL يمرّان `prisma validate`؛ لا فهرس على أي عمود `TEXT`
- `/manifest.webmanifest` عام، والمسارات المحمية تُعيد 307

### غير مُتحقَّق منه — انتبه له

| البند | لماذا |
|---|---|
| **الطباعة على ورق فعلي** | فحصت الوضوح على الشاشة وبالأسود فقط |
| **توفّر اسم FIXEL** | لا وصول لسجلات النطاقات أو العلامات التجارية. افحص `fixel.dz` والعلامة في بلدك. ولاحظ وجود شركة أوروبية اسمها Fixably |
| **الإرسال الحقيقي** | كل المزوّدين على وضع `log` — لم يُختبر Twilio ولا Meta WhatsApp ولا SMTP فعلياً |
| **النشر على cPanel** | الدليل مكتوب ومُختبر منطقياً، لكن لم يُنفَّذ على استضافة حقيقية |
| **الأداء تحت حمل** | لم يُختبر بأكثر من بيانات العرض التجريبية |

## 5) الخطوة التالية المقترحة

**قبل أي ميزة جديدة: انشر واستعمل النظام أسبوعين ببيانات حقيقية.**
ستكتشف احتياجات لم تظهر في التطوير، وستكون أهم من أي بند في القائمة أدناه.

### أول ما تفعله عند النشر

1. تأكّد أن **Setup Node.js App** موجودة في لوحة cPanel — إن لم تكن،
   فالاستضافة PHP فقط ولن يعمل النظام.
2. اتبع `docs/CPANEL.md` خطوة بخطوة.
3. اضبط `NEXT_PUBLIC_APP_URL` على `https://` الحقيقي — وإلا وصلت زبائنك
   روابط `localhost` لا تفتح.
4. فعّل AutoSSL — بدون HTTPS لن يُرسل كوكي الجلسة في وضع الإنتاج.

### قائمة التطوير (مرتّبة بالأولوية)

**عالية — تسدّ ثغرات في نظام قائم**

1. ~~طباعة PDF حقيقية~~ ✅ منجزة
2. مؤشّر **ربحية أمر الصيانة** (سعر الخدمة − تكلفة القطع − وقت الفنّي) — أهم
   رقم في محل صيانة ولا يُعرض حالياً
3. **الجرد الدوري**: شاشة عدّ فعلي ومطابقة. أي فرق (سرقة، كسر) غير مرئي الآن
4. **أرشفة AuditLog**: يُكتب فيه عند كل عملية، وسيصبح أكبر جدول خلال سنتين
5. **حدّ رفع الملفات وضغط الصور**: `public/uploads` ينمو بلا سقف

**متوسطة — عائد تشغيلي مباشر**

6. لوحة طابور الفنّيين مع إعادة التوزيع بالسحب
7. تنبيه الجهاز الراكد (جاهز ولم يُستلم منذ 30 يوماً)
8. تسعير تلقائي من آخر تكلفة شراء
9. إرسال رابط التتبّع تلقائياً عند كل تغيير حالة
10. تقرير الأعطال المتكرّرة حسب الموديل

**منخفضة — بعد الاستقرار**

11. PWA للفنّي (البنية جاهزة — `manifest` موجود)
12. تفعيل تعدّد الفروع في الواجهة (`branchId` موجود في كل الجداول)
13. الفوترة الإلكترونية إن كان بلدك يفرضها

## 8) نقاط أمنية لا تتساهل فيها

- **`ENCRYPTION_KEY` لا يتغيّر بعد أول تشغيل** — هو مفتاح فك تشفير أكواد قفل
  الأجهزة. تغييره يجعلها غير قابلة للقراءة نهائياً. احفظ نسخة خارج الخادم.
- **`AUTH_SECRET`** يوقّع الجلسات **وروابط PDF العامة**. تغييره يُبطل الاثنين.
- **استعادة نسخة احتياطية تحذف كل الجلسات** (تتالي الحذف مع المستخدمين) —
  أي أن الجميع بمن فيهم أنت سيخرجون. متوقَّع، ومذكور في نافذة الاستعادة.
- لا ترفع `.env` إلى المستودع أبداً.
