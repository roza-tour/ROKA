# ROKA — نظام إدارة بيع وصيانة الأجهزة الإلكترونية

نظام ويب متكامل (ERP) لإدارة محلات بيع وصيانة الهواتف والحواسيب والأجهزة اللوحية وأجهزة الألعاب.
عربي بالكامل مع دعم RTL، ومبني ليكون سريعاً وقابلاً للتوسع.

## ما الذي يقدّمه النظام

### لوحة التحكم
مؤشرات لحظية: الأجهزة داخل الورشة، الجاهزة للاستلام، المسلّمة، المتأخرة، مبيعات وأرباح
اليوم والشهر والسنة، المصروفات، صافي الربح، قيمة المخزون، أكثر الخدمات وقطع الغيار طلباً،
رسوم بيانية للإيرادات والمصروفات وحركة الصيانة، ولوحة تنبيهات موحّدة (مخزون منخفض،
أجهزة متأخرة، فواتير غير مسددة، ضمانات على وشك الانتهاء، مصروفات دورية مستحقة).

### الصيانة
- **استقبال الجهاز**: بيانات الجهاز كاملة (النوع، الشركة، الموديل، اللون، الرقم التسلسلي،
  IMEI، كلمة مرور الجهاز مشفّرة)، قائمة الملحقات المستلمة، ووصف العطل مع تصنيفه.
- **تقرير حالة مفصّل**: 23 مكوّناً للفحص تتغيّر حسب نوع الجهاز (شاشة، كاميرات، سماعات،
  مايك، منفذ شحن، أزرار، بصمة، Face ID، شبكة، واي فاي، بلوتوث، بطارية، هيكل، مراوح…)
  بأربع حالات لكل مكوّن، بالإضافة إلى سبع علامات فيزيائية (خدوش، كسور، انحناء، آثار سقوط،
  آثار ماء، صيانة سابقة، براغي ناقصة).
- **تحديد مواضع الأضرار** على مخطط الجهاز بخمسة أنواع علامات ملوّنة.
- **رفع صور الجهاز** و**توقيع رقمي** للعميل والموظف يعملان باللمس والفأرة.
- **وصل استلام بنسختين** (للزبون وللمحل) على صفحة واحدة، يحتوي QR Code وباركود ورقم
  العملية وبيانات العميل والجهاز وتقرير الحالة والملحقات والتواريخ وشروط الضمان والتواقيع.
- **سير عمل الحالات** بانتقالات محكومة: تم الاستلام ← جارٍ الفحص ← انتظار موافقة العميل ←
  انتظار قطعة غيار ← تحت الإصلاح ← جاهز للاستلام ← تم التسليم.
- **بوابة تتبع عامة** للعميل عبر QR Code — يرى مراحل الإصلاح والتكلفة والمبلغ المستحق
  دون الحاجة لحساب.

### كتالوج الخدمات
مُعبّأ مسبقاً بـ **71 خدمة** في 9 تصنيفات: تبديل قطع الهواتف، صيانة اللوحات، برمجيات
الهواتف، تركيب الإكسسوارات، أنظمة الحواسيب، عتاد الحواسيب، الأجهزة اللوحية، أجهزة الألعاب،
وخدمات عامة. لكل خدمة سعر وتكلفة ومدة متوقعة ومدة ضمان، مع تعديل الأسعار بالجملة.

### المخزون
منتجات (أجهزة، قطع غيار، إكسسوارات، مستهلكات) مع باركود EAN-13 صالح يُولَّد تلقائياً،
أسعار شراء وبيع وجملة، حد أدنى للتنبيه، موقع تخزين، مورد، وضمان. ورقة ملصقات باركود
قابلة للطباعة. **سجل حركة كامل** — كل تغيير في الكمية يُسجَّل مع الرصيد بعده والمستند المرجعي.
القطع المستخدمة في الصيانة والمنتجات المباعة تُخصم تلقائياً، وتُرجَع عند الإلغاء.

### الموردون والمشتريات
أوامر شراء باستلام جزئي أو كامل، تحديث تلقائي لأسعار التكلفة عند الاستلام، ومتابعة
أرصدة الموردين.

### نقطة البيع والفواتير
- **نقطة بيع سريعة** تدعم ماسح الباركود (مطابقة فورية عند Enter)، اختصارات لوحة المفاتيح
  (F2 للبحث، F9 للدفع)، وحساب الباقي.
- **فواتير** بخصومات (نسبة أو مبلغ)، ضرائب، كوبونات، دفعات متعددة بطرق مختلفة
  (نقداً، بطاقة، تحويل بنكي، محفظة إلكترونية، شيك، آجل)، وفاتورة قابلة للطباعة مع QR وباركود.
- **خطط أقساط** بتوزيع تلقائي وآخر قسط يستوعب فروق التقريب.
- **إلغاء الفاتورة** يعكس كل الأثر: إرجاع المخزون، تصحيح رصيد العميل، سحب نقاط الولاء،
  وإبطال الضمانات.

### عروض الأسعار
إنشاء، إرسال، قبول/رفض، وتحويل بضغطة واحدة إلى فاتورة أو أمر صيانة، مع نسخة للطباعة.

### الضمانات
تُنشأ تلقائياً عند التسليم أو البيع، مع تنبيهات قبل الانتهاء وإرسال تذكيرات للعملاء.

### المصروفات
14 تصنيفاً افتراضياً (إيجار، كهرباء، ماء، إنترنت، هاتف، رواتب، ضرائب، نقل، أدوات صيانة،
مواد تنظيف، دعاية، شراء معدات، صيانة المحل، أخرى)، مصروفات دورية بتنبيهات استحقاق
وتسجيل دفعة بضغطة واحدة، ورسوم بيانية للتوزيع والتطور.

### التقارير
11 تقريراً: الأرباح والخسائر، المبيعات، المخزون، أفضل العملاء، أفضل الموظفين، أكثر الخدمات،
أكثر قطع الغيار، الأعطال الأكثر تكراراً، الأجهزة المتأخرة، الضمانات، والمصروفات — مع فترات
جاهزة أو مدى مخصّص، وتصدير إلى **Excel** (منسّق بالكامل مع دعم RTL) و**CSV** و**PDF**.

### الموارد البشرية
موظفون بأدوار وصلاحيات دقيقة، حضور وانصراف بساعة حيّة، رواتب مع مكافآت وعمولات وخصومات
وسلف — وصرف الراتب يُسجَّل تلقائياً كمصروف لينعكس على صافي الربح.

### الإشعارات
SMS وواتساب وبريد إلكتروني، بقوالب قابلة للتحرير بثلاث لغات لكل قناة، وقائمة إرسال مع
إعادة محاولة وسجل كامل. الإرسال تلقائي عند تغيير حالة الجهاز.

### أخرى
مواعيد الصيانة، ولاء العملاء بالنقاط، ديون وأقساط، سجل تدقيق كامل لكل عملية حسّاسة،
بحث عام سريع (Ctrl+K)، وضع ليلي، ونسخ احتياطي واستعادة.

## التشغيل السريع

```bash
# 1) تثبيت الحزم
npm install

# 2) إعداد البيئة
cp .env.example .env
# ثم ولّد المفاتيح وضعها في .env:
openssl rand -base64 48   # ← AUTH_SECRET
openssl rand -hex 32      # ← ENCRYPTION_KEY

# 3) إنشاء قاعدة البيانات وتعبئتها
npm run setup

# 4) التشغيل
npm run dev
```

افتح <http://localhost:3000> وسجّل الدخول بالبيانات التي طبعها أمر التعبئة
(افتراضياً `admin` / `Admin@12345`).

> ⚠️ **غيّر كلمة مرور المدير فوراً** بعد أول دخول من «الملف الشخصي ← تغيير كلمة المرور».

## متغيّرات البيئة

| المتغيّر | إلزامي | الوصف |
|---|:---:|---|
| `DATABASE_URL` | ✅ | مسار قاعدة البيانات |
| `AUTH_SECRET` | ✅ | مفتاح توقيع الجلسات — 32 حرفاً على الأقل |
| `ENCRYPTION_KEY` | ✅ | مفتاح تشفير البيانات الحساسة — 64 حرف hex |
| `SESSION_MAX_AGE` | — | مدة الجلسة بالثواني (افتراضي 43200 = 12 ساعة) |
| `NEXT_PUBLIC_APP_URL` | — | العنوان العام — يُستخدم في روابط تتبع الأجهزة |
| `SMS_PROVIDER` | — | `log` \| `http` \| `twilio` |
| `WHATSAPP_PROVIDER` | — | `log` \| `http` \| `meta` |
| `EMAIL_PROVIDER` | — | `log` \| `smtp` |

الوضع الافتراضي لكل مزوّدي الإشعارات هو `log` — يكتب الرسائل في الطرفية بدل إرسالها،
وهو مناسب للتطوير ولمن لم يشترك بعد في خدمة إرسال.

## الأدوار والصلاحيات

سبعة أدوار جاهزة، ويمكن منح أي موظف صلاحيات إضافية فوق دوره:

| الدور | الوصول |
|---|---|
| **مدير النظام** | كل شيء بلا استثناء |
| **مدير المحل** | كل العمليات + عرض التقارير والموظفين |
| **فني صيانة** | أوامر الصيانة، العملاء، عرض المخزون والخدمات |
| **أمين الصندوق** | نقطة البيع، الفواتير، المدفوعات، العملاء |
| **موظف استقبال** | استقبال الأجهزة، العملاء، المواعيد، عروض الأسعار |
| **محاسب** | المصروفات، المدفوعات، التقارير، الرواتب |
| **مشاهدة فقط** | عرض دون تعديل |

الصلاحية بصيغة `module:action` (مثل `invoices:create`). التحقق يتم في **ثلاث طبقات**:
القائمة الجانبية تُخفي ما لا يملكه المستخدم، الصفحة ترفض التحميل، والإجراء الخادمي يرفض
التنفيذ — فلا يكفي إخفاء الزر.

### المبادئ المتبعة

- **كل الحسابات المالية في مكان واحد** (`lib/pricing.ts`) — نفس المنطق على الخادم والعميل،
  فلا تختلف الأرقام المعروضة عن المحفوظة.
- **كل تغيير في المخزون يمرّ من `lib/inventory.ts`** — يضمن تطابق `Product.quantity` مع
  سجل `StockMovement` دائماً.
- **العمليات المركّبة داخل معاملة واحدة** — إنشاء فاتورة يشمل البنود والمخزون والدفعة
  والضمان والولاء ورصيد العميل: إما أن ينجح كله أو لا يُنفَّذ شيء.
- **النصوص تُبنى على الخادم وتُمرَّر إلى مكوّنات العميل** — لتفادي إرسال القواميس الثلاثة
  إلى المتصفح.

## قواعد العمل المهمّة

### حساب الربح
```
الربح الإجمالي = (المجموع بعد الخصم) − تكلفة البنود
صافي الربح     = الربح الإجمالي − المصروفات
```
الإيراد يُحتسب على أساس **تاريخ إصدار الفاتورة** لا تاريخ التحصيل. الفواتير الملغاة
والمسودات مستثناة من كل الحسابات.

### ترتيب حساب الفاتورة
```
1. مجموع البنود بعد خصم كل بند       → subtotal
2. خصم الفاتورة (نسبة أو مبلغ) + الكوبون → discountAmount
3. الضريبة على (subtotal − discount)   → taxAmount
4. الإجمالي                            → total
```

### رصيد العميل
موجب = له رصيد لدى المحل، سالب = عليه دين. البيع الآجل يُنقص الرصيد، والدفعة تزيده.

### القطع في الصيانة
تُخصم من المخزون **فور إضافتها** إلى أمر الصيانة لا عند التسليم — لأن القطعة خرجت فعلياً.
عند إلغاء الأمر أو حذف البند تُرجَع تلقائياً. لذلك عند إنشاء فاتورة من أمر صيانة، تُحوَّل
بنود القطع إلى بنود «مخصّصة» حتى لا تُخصم مرتين.

### انتقالات حالة الصيانة
محكومة بجدول `REPAIR_STATUS_FLOW` — لا يمكن القفز من «تم الاستلام» إلى «تم التسليم» مباشرة.

## الانتقال إلى PostgreSQL

المخطط مصمّم ليعمل على أي قاعدة دون تعديل (لا يستخدم `enum` ولا `Json` على مستوى
قاعدة البيانات):

```prisma
// prisma/schema.prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

```bash
DATABASE_URL="postgresql://user:pass@localhost:5432/roka"
npm run db:migrate
npm run db:seed
```

لدقة مالية أعلى في PostgreSQL، استبدل `Float` بـ `Decimal @db.Decimal(14,3)` في الحقول
المالية قبل الترحيل.

## الإشعارات

القوالب قابلة للتحرير من «الإشعارات ← قوالب الإشعارات»، لكل قناة ولغة قالب مستقل.
المتغيّرات تُكتب بين قوسين مزدوجين وتُستبدل عند الإرسال:

`{{customerName}}` `{{deviceName}}` `{{orderNumber}}` `{{trackingUrl}}` `{{estimatedCost}}`
`{{amountDue}}` `{{warrantyEnd}}` `{{invoiceNumber}}` `{{total}}` `{{shopName}}` `{{shopPhone}}`

كل رسالة تُكتب في قائمة الإرسال أولاً ثم تُرسَل — فلا تضيع رسالة عند انقطاع الشبكة، ويمكن
إعادة المحاولة من الواجهة.

### ربط مزوّد فعلي

```bash
# SMS عبر أي API يقبل JSON
SMS_PROVIDER="http"
SMS_API_URL="https://api.provider.com/send"
SMS_API_KEY="..."

# واتساب عبر Meta Cloud API
WHATSAPP_PROVIDER="meta"
WHATSAPP_TOKEN="..."
WHATSAPP_PHONE_ID="..."

# بريد عبر SMTP (يتطلب: npm i nodemailer)
EMAIL_PROVIDER="smtp"
SMTP_HOST="smtp.gmail.com"
SMTP_PORT="587"
SMTP_USER="..."
SMTP_PASSWORD="..."
```

## النسخ الاحتياطي

من «الإعدادات ← النسخ الاحتياطي». النسخة ملف JSON يحتوي كل الجداول بترتيب يحترم
المفاتيح الأجنبية — يعمل مع أي قاعدة بيانات وقابل للفحص يدوياً، بخلاف نسخ ملف
قاعدة البيانات الخام.

**الاستعادة** مقصورة على مدير النظام، وتتم داخل معاملة واحدة: أي فشل يعيد قاعدة
البيانات إلى حالتها السابقة.

> ⚠️ الاستعادة تُنهي كل الجلسات النشطة — ستحتاج أنت وبقية الموظفين إلى تسجيل الدخول
> من جديد بعدها.

للنسخ التلقائي، أضف مهمة مجدولة تنادي المسار مع كوكي جلسة صالحة، أو انسخ ملف
`prisma/dev.db` دورياً في حالة SQLite.

## الأمان

- كلمات المرور بـ **bcrypt** (12 جولة)، ولا تُخزَّن أبداً بصيغة قابلة للقراءة.
- الجلسات **JWT موقّع** + سجل في قاعدة البيانات — يمكن إبطال أي جلسة فوراً.
- **قفل الحساب** 15 دقيقة بعد 5 محاولات دخول فاشلة.
- **تشفير AES-256-GCM** لكلمات مرور الأجهزة.
- **سجل تدقيق** لكل عملية حسّاسة، مع إخفاء الحقول الحساسة (كلمات المرور، التواقيع) تلقائياً.
- **التحقق من الصلاحيات في الإجراء الخادمي نفسه** — لا يكفي إخفاء الزر.
- **التحقق من المدخلات بـ zod** قبل أي لمس لقاعدة البيانات.
- **حماية من حقن الصيغ** في ملفات CSV المصدَّرة.
- أسماء الملفات المرفوعة **عشوائية** ونوعها محقّق — لا نثق باسم الملف الوارد من المتصفح.
- تعطيل حساب موظف **يُنهي جلساته فوراً**.
- رؤوس أمنية (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`) على كل الطلبات.

### قبل النشر للإنتاج

1. ولّد `AUTH_SECRET` و`ENCRYPTION_KEY` جديدين — **لا تستخدم قيم المثال أبداً**.
2. غيّر كلمة مرور المدير.
3. فعّل HTTPS (الكوكي يصبح `secure` تلقائياً في وضع الإنتاج).
4. انتقل إلى PostgreSQL.
5. اضبط `NEXT_PUBLIC_APP_URL` على العنوان الحقيقي حتى تعمل روابط التتبع.
6. جدول نسخاً احتياطية دورية.

## التطوير المستقبلي

البنية جاهزة لهذه الإضافات دون إعادة بناء:

- **تعدد الفروع**: الجداول تحتوي `branchId` بالفعل، ونموذج `ProductStock` يفصل الكميات
  لكل فرع — يتبقّى واجهة تبديل الفرع وترشيح البيانات.
- **تطبيق الموظفين**: الإجراءات الخادمية منفصلة عن الواجهة ويمكن كشفها كـ API.
- **بوابة العميل**: بوابة التتبع موجودة؛ يمكن توسيعها بحساب عميل كامل.
- **أجهزة نقاط البيع**: شاشة نقطة البيع تعمل باللمس وتدعم ماسح الباركود؛ الطباعة الحرارية
  مهيّأة بأنماط `receipt-thermal` في `globals.css`.
- **الترحيل إلى العملات المتعددة**: `finance.currency` إعداد واحد — يمكن توسيعه لحقل
  عملة لكل فاتورة.
